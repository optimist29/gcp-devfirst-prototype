🚫 METHOD 1: The Flaw-First Anti-Pitch Disqualifiers

When NOT to use Cloud Run (Read this first):

1. Persistent local disk: Instances are ephemeral tmpfs. When instances scale down or crash, disk vanishes. Use Cloud SQL or GCS volumes.

2. 24/7 flat 100% CPU loads: If your servers never sleep, Compute Engine VMs with Committed Use Discounts are ~3x cheaper per core-hour.

3. Massive idle WebSockets: WebSockets are supported, but paying per active container-second for 20,000 mostly-idle open sockets gets expensive. Use Compute Engine or Pub/Sub.

🚫 METHOD 1: The Flaw-First Anti-Pitch Disqualifiers

When NOT to use Spanner:

1. Under 500GB in a single region: Cloud SQL for PostgreSQL is much cheaper and supports all native extensions. Use Cloud SQL.

2. You rely on Postgres extensions: No PostGIS, no pg_vector, no custom C extensions. Spanner implements core SQL and wire protocol, not extension binaries.

3. Sub-millisecond single-row reads: Strong consensus has a physical quorum floor. Expect ~5–8ms p50 reads, not the ~0.5ms of local RAM/Redis.
